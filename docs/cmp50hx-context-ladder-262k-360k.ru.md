# Исследование контекстной лестницы 262K / 360K на Qwen3.6-35B-A3B (RTX-tail, MTP n-max=3)
[English](cmp50hx-context-ladder-262k-360k.md) | **Русский**

## Статус

Завершено 2026-09-16. Конфигурация сервера: `--device CUDA0,CUDA2,CUDA1`,
`--tensor-split 1,1,2.5`, `--ubatch-size 448`, MTP `n-max=3`, среда выполнения без-fmad.
Хост остаётся выведенным из эксплуатации для исследований; все серверы стенда были остановлены
после запусков.

## Настройка

- Промпты лестницы генерируются из корпуса репозитория
  (`benchmarks/scripts/build_context_ladder.py`,
  `benchmarks/prompts/context-ladder.json`): `hello` (13 токенов),
  `context-10k` (9,897 целевых / 9,907 с шаблоном чата), `context-75k`
  (74,999 / 75,009). Они содержат одинаковый префикс корпуса, поэтому запрос на 75k также
  использует частичное повторное применение префикса запроса на 10k.
- Шаги: `context-ladder-steps-test1.json` (одна сессия: hello, 10k, 75k, 75k)
  и `context-ladder-steps-test2.json` (две сессии: A hello/10k/75k/75k,
  B hello/10k/75k/75k, затем снова A и B 75k).
- Запускатор: `benchmarks/scripts/run_context_ladder.py`; телеметрия хоста/GPU:
  `benchmarks/scripts/host_telemetry.py` (0.5 s: загрузка/температура CPU, RAM, swap и
  для каждого GPU температура/загрузка/память/питание). Исходные тайминги, id слота и принятие черновика
  разбираются из `server.log`.
- Запуски 360K используют контекст 368,640. Модель обучалась на 262,144; позиции
  сверх этого используют экстраполяцию RoPE, и качество здесь не измерялось.

## Результаты декодирования и кэша

`pref_eval` — исходная скорость вычисления промпта для фактически вычисленных токенов;
`eff_prefill` — полный промпт (75,009 токенов), делённый на всё время вычисления
промпта, то есть видимая пользователю пропускная способность префилла; `cache` — доля
промпта, обслуженная из кэша промптов.

## Выводы

1. **Кэш промптов работает точно.** Повтор одного и того же промпта 75k требует 4
   вычисленных токена (~100% попадание) и только время генерации: 6.9 s для
   Теста 1 против 229.6 s для холодного префилла.
2. **Повторное применение префикса работает частично.** Промпт 75k имеет общий с 10k
   префикс корпуса; в режиме одной сессии повторно использовался 9,391 токен (12.5% от 75k),
   повышая эффективный префилл с 289.6 до 331.1 t/s. В режиме двух сессий чередование
   слотов может пропустить этот префикс, поэтому на шаге 3 Теста 2 были вычислены
   все 75,009 токенов.
3. **Восстановление KV-кэша в RAM хоста работает между сессиями.** В Тесте 2 вторая
   сессия B повторно использовала состояние A для 75k (4 вычисленных токена) без пересчёта, и
   последующие повторы A/B сделали то же после смены слотов.
4. **Эффективный префилл**: ~473 t/s для 10k; ~331 t/s и ~331 s wall для холодного
   75k в режиме одной сессии (75k × 0.29 ms/token плюс рост внимания).
   Контекст 360k не меняет эти скорости.
5. **Генерация**: 96-103 t/s на коротком контексте, ~60 t/s при занятом контексте 75k
   в режиме одной сессии. В устойчивом состоянии двух сессий она устанавливается
   на ~45.5 t/s (-23% против первой кэшированной генерации), с неизменным
   принятием (средняя длина черновика 3.1-3.3). Причина здесь не была изолирована;
   телеметрия температуры/питания не показывает троттлинга (RTX 57-59 C, 286-289 W), поэтому
   это, вероятно, обработка сервером/KV двух активных состояний 75k, а не
   GPU.
6. **360K помещается без перераспределения слоёв.** KV увеличивается примерно на ~1.2 GiB (2.92 ->
   4.11 GiB attention KV); принятый split `1,1,2.5` это поглощает. Выборочные
   пики: CMP0 8,287, RTX 21,940, CMP2 7,585 MiB. Запас RTX сокращается примерно до
   0.6 GiB, так что 360k жизнеспособен, но тесен. Обученный контекст модели —
   262,144; качество экстраполяции RoPE выше этого не измерялось.
7. **Давление на хост при 360k с двумя слотами**: swap достиг 3.98 GiB из 4 GiB
   (`--cache-ram 8192` плюс два состояния 75k и контрольные точки). Загрузка CPU оставалась
   ниже 25% и ниже 52 C в каждом запуске.
